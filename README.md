# ダービーゲームスタジオ

馬主になって競走馬を育て、レースに出し、血統をつないでいく macOS 用の競馬シミュレーションゲームです。
馬名・人名・レース名はすべて架空です。競馬場のコースは JRA 公式のコース紹介をもとにしています。

- デスクトップ: [Tauri v2](https://tauri.app/)
- ゲームの中身: Rust
- 画面: React + TypeScript

## 遊び方

1 週ごとにゲームが進みます。年間は 52 週です。

| タブ | できること |
| --- | --- |
| レース | 今週のレースを選び、出走登録と馬券の購入をして、レースを見る |
| 育成 | 調教、休養、放牧、馬具、お任せ調教、自動出走 |
| 厩舎 | 調教師・騎手・作戦の選択、調教師からの提案、馬の売却、引退 |
| 血統 | 持ち馬の血統表と血統データベース |
| 繁殖 | 種付け、繁殖馬の売買、1 歳馬のセリ、牧場の拡張、海外遠征 |
| カレンダー | 1 年分のレース日程 |
| 情報 | 騎手と競馬場 |
| 実績 | 受賞、殿堂、現役馬の実績、ライバル、調教師の成績 |

所持金が 0 になるとゲームオーバーです。オートプレイを使えば、週を自動で進められます。

### 馬の補充

馬は 9 歳で引退して繁殖に入り、自動では補充されません。種付けかセリで後継の馬を用意してください。仔馬が走れるようになるまで、種付けから 3 年かかります。

- 3 年後も走っている馬(お腹の仔馬を含む)が 4 頭未満になると、画面の上部に表示が出て、種付けシーズンの始めにお知らせが届きます。
- オートプレイは、出走できる馬が 4 頭未満になったところで止まります。もう一度始めれば、そのまま進められます。

### 出走頭数と除外

レースごとに登録頭数が決まり、次のように出走馬が決まります。

- 出走するのは **6〜18 頭** です。G1 は 16 頭以上、G2・G3 は 12 頭以上と、重賞ほど多くなります。
- フルゲートは競馬場で決まります。札幌・函館・福島は 16 頭、それ以外は 18 頭です。
- 登録頭数がフルゲートを超えると抽選があり、**出走登録した馬でも除外されることがあります**。超過が多いほど除外されやすくなります。
- 前走で 5 着以内の馬は優先出走権があり、除外されません。除外された馬にも次走の優先出走権が付きます。
- G1 は獲得賞金かトライアルの優先出走権で出走が決まるので、抽選はありません。
- 7 頭以下のレースでは、複勝は 2 着までの的中になります。
- 出馬表には単勝オッズの低い順の人気を表示し、結果には着差と人気を表示します。
- ワイドは、選んだ 2 頭がどちらも 3 着以内に入れば的中です。
- 天候は馬場状態に合わせて決まり、天候そのものはレースに影響しません。
- フリーレースと海外遠征は、常に 18 頭で走ります。

### 地方・交流重賞

大井、川崎、船橋、園田の 4 場で、ダートの交流重賞(JpnI〜JpnIII)が行われます。フルゲートは大井 16 頭、川崎と船橋 14 頭、園田 12 頭で、頭数は重賞の決まりより少ないことがあります。コースの数値は概算です。

### 障害レース

3 歳以上の馬は、厩舎タブで障害に転向できます。障害練習で飛越を鍛え、飛越 30 以上で受けられる障害試験(費用 100)に合格すると、障害レースに出られます。平地との掛け持ちもできます。

- **クラス:** 障害未勝利、障害オープン、J・G3〜J・G1 の順で、障害の勝ち数で決まります。平地の勝ち数には数えません。
- **飛越:** 血統で引き継がれ、馬の血統が伸びる上限を決めます。騎手には別に「障害の腕」があり、飛越の助けになります。
- **競走中止:** 障害では飛越のミスや落馬が起こります。平地でもごくまれに起こります。中止した馬は賞金なしで、故障することがあります。その馬の馬券は外れで、複勝の枠は出走頭数で決まります。
- 調教師が自動で障害に転向させることはありません。転向した馬には、障害レースを優先して出走させます。

### 馬の個性

- **成長型:** 早熟、普通、晩成があり、成長型に応じた年齢で能力のピークを迎えます。仔馬の成長型は両親の成長型の中間を中心に、ある程度ばらつきながら引き継がれます。種付け画面で見込みを確認できます。
- **季節:** 夏負け(第27〜35週)、冬負け(第1〜8週と第49〜52週)、夏に強い馬がいて、該当する時期は出馬表に表示されます。季節の影響を受けない馬が多数です。フリーレースには影響しません。
- **去勢:** 牡馬を去勢すると、気性が穏やかになり、しばらく放牧に出ます。繁殖入りはできなくなり、引退すると厩舎を去ります。三冠レースにも出られません。
- **馬具:** メンコ、シャドーロールに加えて、ブリンカーを着けられます。少し速くなりますが、掛かりやすくなります。

### 東西の所属

騎手 10 人と調教師 10 人は、5 人ずつ美浦(東)と栗東(西)に分かれています。
調教師が騎手を手配するときは、予算内で同じ所属の騎手を優先します。騎手を自分で選ぶときは、所属に関係なく選べます。

### 騎手・調教師の入れ替わりとリーディング

騎手と調教師は年が変わるときに引退し、同じ所属の新人が入ります。新人騎手は腕を上げていき、新しい調教師は前任者の厩舎を引き継ぎます。

実績タブには、騎手、調教師、種牡馬の年間の勝利数の順位(リーディング)が出ます。実際に走るのは自分の馬が出るレースだけなので、それ以外の勝利数は能力と乱数から計算した架空の数字です。

## 開発

必要なもの: Rust、Node.js、Xcode Command Line Tools

```bash
make dev
```

開発モードで起動します(ホットリロードあり)。

```bash
make test
```

画面(Vitest)とゲームの中身(cargo test)のテストをすべて実行します。

```bash
make app
```

`.app` をビルドします。出力先は `src-tauri/target/release/bundle/macos/` です。

```bash
make dmg
```

インストーラーの `.dmg` をビルドします。

```bash
make clean
```

ビルドの生成物を削除します。

### 開発ルール

テスト駆動で開発します。テストを先に書き、失敗を確認してから実装します。
ゲームのルールは Rust 側に置き、画面には表示と操作だけを置きます。詳しくは [docs/CLAUDE_PROMPT.md](docs/CLAUDE_PROMPT.md) を見てください。

一部の不具合はリリースビルドでだけ現れるため、`cargo test --release` も実行してください。
レースの結果とオッズは種(シード)から決まるので、同じ種なら同じ結果になります。

### セーブデータ

`~/Library/Application Support/com.toshiaki0315.derbygame/save.json` に保存します。
セーブ形式には版番号(`save_version`)があります。現在は 2 で、馬ごとの情報は `field` の各馬が持ちます。

古いバージョンのセーブデータは、足りない項目を補って読み込みます。馬の情報を別々の配列で持っていた版 1 のセーブも読み込めて、次のセーブから版 2 で保存されます。版 1 の実物を `game/tests/save_version_1.json` に置き、テストで読み込みを確かめています。
新しい版のゲームで作られたセーブデータは読み込めません。

## ソースコードの構成

### ゲームの中身(`src-tauri/src/`)

| ファイル | 内容 |
| --- | --- |
| `game/` | ゲーム全体。下の表を参照 |
| `race.rs` | レースのシミュレーション(ペース、脚質、掛かり、着差) |
| `entries.rs` | 登録頭数、フルゲート、抽選 |
| `bets.rs` | 馬券の種類、的中判定、人気 |
| `rivals.rs` | 相手馬の生成、ライバル馬、乱数 |
| `bloodline.rs` | 血統データベースと配合 |
| `calendar.rs` | 年間のレース日程 |
| `course.rs` | 競馬場のコースと馬との相性、東西の区分 |
| `jockey.rs` / `trainer.rs` | 騎手と調教師 |
| `form.rs` / `track.rs` / `weight.rs` | 成長と距離適性、馬場状態、斤量 |
| `commentary.rs` | レースの実況 |
| `horse.rs` | 馬の基本データと馬名のルール |

`game/` の内訳は次のとおりです。

| ファイル | 内容 |
| --- | --- |
| `mod.rs` | `Game` 本体と新規ゲームの作成 |
| `consts.rs` | ゲームバランスの数値 |
| `types.rs` | 保存するデータと画面に渡すデータの型(厩舎の馬 `StableHorse` など) |
| `commands.rs` | 画面から呼ばれる Tauri コマンド |
| `state.rs` | 画面に渡す状態の組み立て |
| `save.rs` | セーブとロード |
| `week.rs` | 週の進行と自動出走 |
| `racing.rs` | 出走表、出走登録、騎手の手配 |
| `betting.rs` | オッズ、馬券の購入、レースの実行 |
| `stable.rs` | 厩舎の馬の管理、故障、預託料、売却 |
| `training.rs` | 調教と調教師の提案 |
| `breeding.rs` | 繁殖、種付け、セリ、牧場 |
| `bloodlines.rs` | 持ち馬と血統データベースの対応 |
| `honours.rs` | ライバル、目標、受賞、殿堂 |
| `leading.rs` | リーディング |
| `staff.rs` | 騎手と調教師の入れ替わり |
| `abroad.rs` | 海外遠征 |
| `tests/` | `game/` のテスト。題材ごとのファイルに分かれ、共通の準備処理は `tests/mod.rs` にあります。`tests/commands.rs` は画面と同じ形で命令を呼び、命令名と引数名が画面と合っていることも確かめます |

### 画面(`src/`)

| ファイル | 内容 |
| --- | --- |
| `App.tsx` | 全体の枠組みとタブの切り替え |
| `useGame.ts` | 画面の状態と操作をまとめるフック。中身は `hooks/` に分かれています |
| `hooks/` | 共通の状態(`useCore`)、レースと出走表(`useRaces`)、馬券(`useBetting`)、レースの再生(`useRaceShow`)、オートプレイ(`useAutoplay`)、繁殖(`useBreeding`)、競馬場(`useCourses`)、厩舎の馬(`useStable`) |
| `view.ts` | 状態から計算して画面に渡す値 |
| `types.ts` | ゲームの中身とやり取りするデータの型 |
| `labels.ts` | 共通の文言と小さな計算 |
| `widgets.tsx` | 共通の小さな部品 |
| `tabs/` | タブごとの画面。レース画面は `RaceTab`、`BetPanel`、`RacePanel` に分かれています |
| `Bloodline.tsx` / `Calendar.tsx` | 血統データベースとカレンダー |
| `CourseMap.tsx` / `courseShapes.ts` / `raceShow.ts` | コース図とレースの見せ方 |
| `gates.ts` / `naming.ts` | 枠番の色と馬名のルール |
